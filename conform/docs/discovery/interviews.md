# Interview guides

Thirty minutes each. Ask for the last real example before asking for an opinion. Nobody has been interviewed yet; these are the guides.

## Designer

1. Show me the last screen that shipped and didn't match what you drew. Who noticed?
2. Where do you go to check which value is right, Figma or the running product?
3. Which parts of the system do people work around, and what do they do instead?
4. What would you let a machine block? What would you never let it block?
5. How do you change a token today, and how do you find out who it broke?

## Console engineer

1. Open the last pull request an agent wrote for you. What did you fix by hand?
2. What does the agent know about the design system, and how does it know?
3. When a check fails on your pull request, what makes you trust it or ignore it?
4. Which checks do you skip now, and why?
5. How long can a review take before you stop waiting for it?

## Platform owner

1. Which repositories would you start with, and which would you leave until last?
2. Who can make a check required, and who gets paged when it's wrong?
3. What do your runners allow in and out?
4. What did the last tool you rolled out to every team get wrong?
5. What has to be true on day 30 for you to say yes to all 12?

## Security reviewer

1. What data may leave the network, and what needs a contract first?
2. Which permissions on a GitHub App do you refuse?
3. Where do secrets live and how are they rotated?
4. What do you need to see before code from a fork runs on your machines?
5. What would make you switch this off without asking us?
